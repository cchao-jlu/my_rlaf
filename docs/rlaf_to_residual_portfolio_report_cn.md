# 从 RLAF 到强求解器剩余实例组合求解：阶段性工作与效果汇报

## 一、总体目标变化

这个项目最初的目标，是研究神经网络能否给 SAT 求解器提供有效引导。核心思想不是用神经网络替代求解器，而是让神经网络低频地输出一次或少数几次引导信息，再交给传统求解器完成搜索。

随着实验推进，目标逐步从“神经引导是否能提升一个求解器”升级为更严格的问题：

> 在 March 和 CaDiCaL 这类强求解器都失败之后，神经引导是否还能作为剩余实例上的补充组合策略，额外解出一批实例。

当前最主要的研究主线已经变成：

> 固定强求解器先跑；只在 March 与 CaDiCaL 都未解出的剩余实例上，比较固定预算的神经重启组合方法和同预算的非神经重跑组合方法。

这个主线比早期结果更难，但也更有说服力，因为它不再和弱基线比较，而是正面承认强求解器的能力，并检验神经方法是否有互补价值。

## 二、第一阶段：原始 RLAF

原始 RLAF 的结构可以概括为：

```text
公式图 -> 图神经网络 -> 一次性求解引导 -> 加权求解器 -> 求解器反馈 -> 强化学习更新
```

它的关键特点是低频引导：

- 不是每次变量决策都调用神经网络。
- 不是让神经网络直接求解公式。
- 而是在求解开始前给传统求解器一个全局偏置。

原始 RLAF 的价值在于证明了这条路线可行：神经网络输出的引导确实能影响求解器搜索，并在中等规模实例上带来一定收益。

但它的问题也很明显：随着实例变难，单次静态引导的效果下降，尤其在 350、400 变量规模上覆盖率明显不足。

历史 60 秒评估结果如下：

| 规模 | 方法 | 解出数量 / 200 | 平均时间 |
| --- | --- | ---: | ---: |
| 300 | 原始 RLAF，一次性引导 | 200 / 200 | 7.506 秒 |
| 350 | 原始 RLAF，一次性引导 | 108 / 200 | 34.593 秒 |
| 400 | 原始 RLAF，一次性引导 | 50 / 200 | 47.730 秒 |

可以看到，300 规模效果完整，但到 350 和 400 后，单次引导的覆盖率不足。

## 三、第二阶段：Balanced Improver 反馈改进器

Balanced Improver 不是简单调参版 RLAF，而是改变了模型使用求解器反馈的方式。

它的流程是：

```text
公式图 -> 图神经网络 -> 初始引导
初始引导 -> 求解器短时间预热 -> 全局反馈状态
公式图 + 全局反馈状态 -> 图神经网络 -> 改进后的第二次引导
第二次引导 -> 求解器正式搜索
```

也就是说，它明确训练模型学习：

> 给定公式和求解器早期搜索反馈，如何生成更好的下一步引导。

这比原始 RLAF 多了一个关键能力：模型不只看静态公式结构，还能利用求解器已经暴露出来的搜索状态。

Balanced Improver 的历史长跑结果很强，但需要注意：这些历史结果不是当前严格 60 秒外部超时协议下得到的，所以不能直接和当前 60 秒主表混在一起比较。

历史长跑结果：

| 规模 | 方法 | 解出数量 / 200 | 平均时间 | 最大源记录时间 |
| --- | --- | ---: | ---: | ---: |
| 300 | Balanced Improver | 200 / 200 | 4.835 秒 | 23.569 秒 |
| 350 | Balanced Improver | 200 / 200 | 47.006 秒 | 265.413 秒 |
| 400 | Balanced Improver | 200 / 200 | 763.915 秒 | 5449.880 秒 |

如果只做事后 60 秒截断诊断，结果是：

| 规模 | 方法 | 事后 60 秒内解出 | 平均时间 |
| --- | --- | ---: | ---: |
| 300 | Balanced Improver | 200 / 200 | 4.684 秒 |
| 350 | Balanced Improver | 132 / 200 | 30.961 秒 |
| 400 | Balanced Improver | 52 / 200 | 45.975 秒 |

这个阶段的结论是：反馈条件下的一步改进是有效的，尤其在 350 规模上相对原始 RLAF 有明显改善；但在 400 规模严格 60 秒口径下，提升仍然有限。

## 四、Balanced Improver 之后的总体变化

Balanced Improver 之后，项目的重点发生了明显变化。

前两个阶段主要证明：

- 神经网络可以低频地给求解器提供有用引导。
- 求解器早期反馈可以帮助模型生成更好的第二次引导。

但继续推进时遇到的问题是：神经引导不是稳定单调收益。有些实例明显加速，有些实例会变慢，有些实例原本能解出，启用神经引导后反而失败。因此后续工作不再只是“让模型更强”，而是同时解决三个问题：

1. 模型如何更细粒度地利用求解器运行信息。
2. 如何判断什么时候启用神经引导，避免伤害原本能解出的实例。
3. 在更强基线下，神经方法到底还有没有真正互补价值。

因此 Balanced Improver 之后的主线可以分成四个阶段：

| 阶段 | 核心问题 | 主要工作 | 当前结论 |
| --- | --- | --- | --- |
| 事件状态与适配器 | 如何利用更细的求解器运行信号 | 变量级状态、事件适配器、门控残差更新 | 有助于表达局部反馈，但需要风险控制 |
| 选择器风险控制 | 什么时候启用神经引导 | 保守选择器、反事实风险选择器、在线一致选择器 | 在旧 Glucose 工作流中能减少伤害、改善稳定性 |
| 局部边界修正 | 过于保守时如何重新打开少量正例 | 局部 reopen 规则 | 能降低平均时间，但不增加解出数量 |
| 强求解器剩余实例 | March/CaDiCaL 都失败后是否还有互补价值 | 神经采样组合、探测排序、同预算非神经对照 | 协议更强，但当前模型覆盖率仍偏低 |

## 五、模型层面的改动：从全局反馈到事件适配器

Balanced Improver 使用的是图级全局反馈状态。也就是说，求解器预热之后，把整体搜索统计压缩成一个全局向量，再让图神经网络基于“公式图 + 全局状态”输出第二次引导。

后续模型改动进一步尝试引入更细的求解器运行信息，核心方向是事件状态与适配器。

### 5.1 从图级状态扩展到变量级状态

原始 RLAF 的输入基本是静态公式图。Balanced Improver 加入了图级全局状态。后续版本进一步支持变量级求解器状态，也就是让每个变量或文字携带来自求解器事件的统计特征。

这样做的动机是：SAT 求解器的困难不只体现在整张公式的全局统计上，也体现在局部变量的搜索行为上。例如某些变量在传播、冲突、学习子句、极性变化中可能暴露出更强的局部信号。

模型上对应的变化包括：

- 支持图级 `global_state_dim`。
- 支持变量级 `var_state_dim`。
- 支持把求解器事件状态接入图神经网络输出层。
- 支持不同的状态融合方式，例如残差式融合、门控融合、极性门控融合。

这一步的意义是：模型不再只是“看公式结构”，也开始看“求解器在这个公式上怎么搜索”。

### 5.2 事件适配器

事件适配器的目标是：在已有基础引导上，根据求解器事件状态产生一个修正量。

可以理解为：

```text
基础图神经网络 -> 基础引导
求解器事件状态 -> 适配器修正量
基础引导 + 受控修正量 -> 最终引导
```

这个设计比重新训练一个完整大模型更保守。它更像是在原有引导上做局部修正，而不是完全替换原始策略。

代码层面支持了多种控制机制：

- 修正量缩放，避免适配器输出过大。
- 修正量裁剪，限制单次修改幅度。
- 事件门控，只在某些事件特征满足条件时启用。
- 极性门控，控制变量正负极性方向上的修改。
- 图级门控，根据整张公式的统计决定是否启用适配器。

这些设计背后的核心思想是：神经引导有收益，但也有风险；模型结构本身就应该限制不可靠修正的影响范围。

### 5.3 反事实特征与选择器特征

后续还加入了面向选择器的图级特征，例如：

- 基础引导强度均值。
- 基础引导不确定性。
- 适配器修改幅度。
- 事件门控平均值。
- 事件质量集中度。
- 基础引导与事件信号的相关性。

这些特征不是直接用来求解，而是用来判断“这个实例是否适合打开神经适配器”。

这意味着主线从单纯训练求解模型，转向了“求解模型 + 风险选择器”的组合。

## 六、选择器风险控制

在 Balanced Improver 之后，项目进入了“什么时候该用神经引导”的问题。

原因是神经引导不是总能带来收益。有些实例会加速，有些实例会变慢。因此需要一个选择器判断：哪些实例应该启用神经引导，哪些实例应该保守地交给原求解器。

这一阶段做过多种选择器，包括反事实风险选择器、两阶段风险控制器、在线一致选择器，以及局部边界修正。

### 6.1 反事实风险选择器

反事实风险选择器的思想是：不要只看适配器可能带来的加速，也要重点预测它是否会伤害原本能解出的实例。

它使用基础求解结果和适配器求解结果构造训练信号，并用图级特征预测是否启用适配器。训练时更重视负例，也就是更重视“启用后变差”的情况。

一个典型配置中，选择器特征包括：

- `base_rho_mean`
- `delta_mu_abs_mean`
- `event_gate_mean`
- `event_top10_mass`
- `rho_event_corr`

它的策略是安全优先：宁可少打开适配器，也要尽量避免丢掉基础求解器能解出的实例。

这条线的结论是：风险控制方向是必要的，但早期反事实风险选择器没有形成强主结果。在 300/350 的独立评估中，它没有稳定超过一次性引导或固定门控策略。因此它适合作为风险控制探索，不适合作为最终主线。

### 6.2 在线一致选择器

在线一致选择器进一步强调：训练时选择器看到的证据，要尽量接近测试时真实可获得的证据，避免用离线统计造成虚高结果。

它的目标不是激进地打开更多神经引导，而是保守地保留那些稳定有利的情况。

当前 60 秒协议下的对齐结果如下：

| 规模 | 方法 | 解出数量 / 200 | 平均时间 |
| --- | --- | ---: | ---: |
| 300 | 当前一次性引导 | 200 / 200 | 15.311 秒 |
| 300 | 在线一致选择器 | 200 / 200 | 7.272 秒 |
| 350 | 当前一次性引导 | 108 / 200 | 43.741 秒 |
| 350 | 在线一致选择器 | 109 / 200 | 33.815 秒 |
| 400 | 当前一次性引导 | 50 / 200 | 47.752 秒 |
| 400 | 在线一致选择器 | 56 / 200 | 46.222 秒 |
| 400 | 加局部边界修正 | 56 / 200 | 45.498 秒 |

这一阶段的效果是明确的：在 Glucose 工作流内部，选择器能减少神经引导带来的风险，保留正收益，并改善部分难例表现。

在完整 400 规模评估中，在线一致选择器的结果是：

| 方法 | 实例数 | 解出数量 | 平均时间 |
| --- | ---: | ---: | ---: |
| 一次性引导 | 200 | 50 | 47.7517 秒 |
| 旧 compact 主线 | 200 | 56 | 46.3484 秒 |
| 在线一致选择器 | 200 | 56 | 46.2217 秒 |
| pairwise veto 对照 | 200 | 52 | 46.8755 秒 |

它的主要贡献不是大幅增加解出数量，而是把风险控制得更一致：在不牺牲 56/200 解出数量的前提下，平均时间略优于旧 compact 主线。

### 6.3 局部边界修正

在线一致选择器偏保守，因此会出现另一类问题：一些本来应该打开神经适配器的边界样本被关闭了。

局部边界修正就是为了解决这个问题。它不是重新设计一个全局选择器，而是在非常小的一批候选样本上，用局部规则重新打开适配器。

完整 400 规模评估结果如下：

| 方法 | 实例数 | 解出数量 | 平均时间 | 总时间 |
| --- | ---: | ---: | ---: | ---: |
| 一次性引导 | 200 | 50 | 47.7517 秒 | 9550.3325 秒 |
| 旧 compact 主线 | 200 | 56 | 46.3484 秒 | 9269.6778 秒 |
| 在线一致选择器 | 200 | 56 | 46.2217 秒 | 9244.3337 秒 |
| 局部边界修正 | 200 | 56 | 45.4976 秒 | 9099.5283 秒 |

局部边界修正只触发了 4 个候选实例，其中两个明显加速：

| 实例 | 在线一致时间 | 局部修正时间 | 变化 |
| --- | ---: | ---: | ---: |
| 3sat_46.cnf | 29.8371 秒 | 0.5256 秒 | -29.3115 秒 |
| 3sat_196.cnf | 26.1159 秒 | 9.6220 秒 | -16.4939 秒 |

这说明局部修正确实能修补过保守选择器的一些边界错误。

但它仍然不应作为最终主线，因为它没有增加解出数量，主要是降低平均时间；而且它仍然是在旧 Glucose 神经工作流内部取得的结果。March 和 CaDiCaL 这类强求解器太强，如果最终只证明“在旧 Glucose 神经工作流里有提升”，审稿人很容易质疑基线不够强。

## 七、主线变化：为什么转向强求解器剩余实例

新的主线不是否定前面的工作，而是把问题变得更严格。

以前的问题是：

> 神经引导能不能提升某个求解器工作流？

现在的问题是：

> 强求解器 March 和 CaDiCaL 都失败后，神经引导还能不能提供额外互补能力？

这有三个优点。

第一，基线更强。March 和 CaDiCaL 先跑，神经方法只处理它们都失败的剩余实例。

第二，预算更公平。神经方法多花的采样、探测、正式求解时间，都要和同预算的非神经重跑组合比较。

第三，结论更清楚。如果神经方法能在同预算下比非神经重跑多解实例，就能说明它不是单纯“多花时间”，而是提供了不同的搜索方向。

这次主线变化的实质是：

| 旧主线 | 新主线 |
| --- | --- |
| 在 Glucose 神经工作流内比较不同引导策略 | 在 March/CaDiCaL 都失败后检验神经互补性 |
| 重点看是否提高旧求解流程性能 | 重点看是否能解出强求解器剩余实例 |
| 基线较容易被质疑不够强 | 基线更接近顶会审稿要求 |
| 选择器是主要方法点 | 模型覆盖率、固定预算组合、同预算对照共同构成主线 |
| oracle 或 focused case 容易被质疑 | oracle 只做诊断，主结果必须是固定非 oracle 策略 |

## 八、当前强求解器剩余实例协议

当前协议是：

1. 先生成转变区间随机 3-SAT 实例。
2. 规模包括 410、425、440，每个规模 50 个实例。
3. 分别用 March 和 CaDiCaL 在 60 秒预算下求解。
4. 只有两者都未解出的实例，才进入剩余实例集合。

目前得到的剩余实例数量是：

| 规模 | 候选数量 | March/CaDiCaL 都未解出 |
| --- | ---: | ---: |
| 410 | 50 | 5 |
| 425 | 50 | 14 |
| 440 | 50 | 30 |
| 合计 | 150 | 49 |

这 49 个实例是当前门控实验的数据源。它们不是最终论文主结果，只是用来判断当前模型是否值得继续做选择器和正式对照实验。

门控规则是：

- 每个剩余实例生成 16 个神经引导样本。
- 使用同一个采样种子 1729。
- 每个样本给 March 60 秒。
- 如果 16 个样本中任意一个解出，该实例记为神经采样上界命中。

这个结果叫“上界诊断”，不是最终方法结果。因为它事后看了 16 个样本里有没有成功样本，不能作为可部署方法声称。它只回答一个问题：

> 当前模型在这些剩余实例上有没有足够潜力。

## 九、强求解器剩余实例线中的方法改动

转向强求解器剩余实例后，方法也发生了明显变化。

### 9.1 从单次引导变成采样组合

早期 RLAF 和 Balanced Improver 主要关注一次或两次引导。当前剩余实例线更强调采样组合：

```text
同一个剩余实例 -> 生成多个神经引导样本 -> 每个样本对应一次 March 重启尝试 -> 形成神经组合求解
```

这样做的原因是：对强求解器都失败的实例，单个神经引导命中概率很低。与其押注一个引导，不如让模型产生多个不同搜索方向，再用固定预算筛选和运行。

### 9.2 从最终求解结果扩展到早期探测信号

为了避免把 16 个样本全部跑满，当前方法加入了短时间探测。每个神经样本先用 March 跑一个很短的内部预算，例如 1 秒，收集搜索进展统计。

目前使用过的探测信号包括：

- 是否在探测阶段直接解出。
- 死端数量。
- 决策数量。
- 单元传播数量。
- March 内部计数器。

一个简单但有效的规则是：

```text
如果有样本在探测阶段解出，就优先运行这些样本；
否则按照探测阶段死端数量等进展信号排序；
再选择 top-k 个样本进入正式 60 秒运行。
```

这条线的重点不是让选择器事后挑样本，而是把选择规则固定下来，确保最终结果可复现、可审计。

### 9.3 从神经收益转向公平预算比较

当前协议要求同时记录：

- 神经样本生成时间。
- 探测阶段 CPU 和实际时间。
- 正式运行阶段 CPU 和实际时间。
- 失败样本的封顶预算。
- 每个实例分配到的总剩余预算。

最关键的是：神经组合方法必须和同预算的非神经重跑组合比较。

非神经对照包括：

- March 默认重跑或可审计扰动版本。
- CaDiCaL 不同种子或配置。
- March 与 CaDiCaL 混合重跑日程。
- 与神经方法相同的剩余 CPU 预算。

这一步非常重要。否则审稿人会认为神经方法只是多花了预算，而不是提供了新的搜索能力。

### 9.4 从 focused case 转向完整 denominator

早期 March 采样实验中已经看到一些 focused positive case，例如某些 March/CaDiCaL 都未解出的实例能被神经采样解出。

但 focused case 不能作为最终主结果，因为它容易被认为是事后挑选。

因此当前协议要求报告完整分母：

| 数量 | 含义 |
| --- | --- |
| candidate N | 一开始生成的候选实例总数 |
| March solved | March 解出的数量 |
| CaDiCaL solved | CaDiCaL 解出的数量 |
| union solved | 两个强求解器合并解出的数量 |
| both-unknown residual R | 两者都未解出的剩余实例数量 |
| oracle neural coverage | 神经采样上界覆盖 |
| fixed neural solves | 固定选择策略下神经组合解出 |
| fixed non-neural solves | 同预算非神经组合解出 |
| neural-only | 神经组合独有解出 |
| non-neural-only | 非神经组合独有解出 |

这能避免只展示成功案例，也能让最终结论更可防守。

### 9.5 系统与审计层面的改动

为了支撑强求解器剩余实例主线，项目也做了不少系统层面的改动。这些改动本身不是方法贡献，但决定了实验能否被严格复现和审计。

主要包括：

- 给加权 March 加入内部 CPU 预算参数，避免只依赖外部进程强杀。
- 让 March 在超时返回未知结果时仍然输出内部搜索计数器。
- 在求解器封装层解析 March 的死端数、决策数、传播数、必要赋值数、CPU 时间等统计。
- 让采样组合运行器支持实例级产物、断点续跑和输出目录锁，避免长实验中途失败或并发污染结果。
- 给剩余实例协议加入预算审计，检查神经组合和非神经对照是否按实例匹配同样的剩余 CPU 预算。
- 给门控决策记录检查点路径、检查点哈希、结果文件哈希和正式分母，避免模型版本与实验结论脱钩。

这些改动的意义是：当前主线不只是“跑出几个神经样本能解”，而是要保证每个结果都能回溯到固定模型、固定数据、固定预算和固定选择规则。

## 十一、当前最新模型与实验状态

当前最新分支是 ResidualProgressDiverse。

更具体地说，这个分支从之前的 elite replay 模型继续训练，目标函数从单纯追求是否解出，扩展为面向剩余实例的复合目标：

- 已解样本仍然优先。
- 未解样本如果在 March 搜索中推进得更深，也会得到更好的训练信号。
- 进展信号包括死端数和决策数等 March 内部统计。
- 对未解样本加入多样性奖励，鼓励多个采样引导走向不同搜索区域。

## 十二、目前整体效果评价

从项目演化看，已经完成了三类实质工作。

第一类是证明神经低频引导可行。原始 RLAF 证明了公式图到求解器引导这条路线可以工作，但难实例覆盖不足。

第二类是证明求解器反馈有价值。Balanced Improver 说明，利用早期求解器反馈生成第二次引导，比完全静态的一次性引导更合理，在 350 规模上有明显收益。

第三类是把实验协议推向更强、更公平的方向。选择器阶段解决了神经引导的风险控制问题；当前剩余实例组合求解阶段进一步把问题放到 March 和 CaDiCaL 都失败后的场景中，并要求同预算非神经对照。

但是，从当前强求解器剩余实例结果看，性能还没有达到顶会主结果要求。核心瓶颈不是选择器，而是模型本身在剩余实例上的上界覆盖率太低。也就是说，很多实例不是“有好样本但选择器没选到”，而是当前 16 个样本里本身就很少出现能解出的引导。

## 十三、当前主线与下一步

当前主线应保持为：

> 强求解器失败后的剩余实例组合求解。

具体目标是：

> 在更大的转变区间剩余实例集合上，固定神经采样和选择规则，比较神经重启组合与同预算非神经重跑组合，验证神经方法是否能稳定多解一批强求解器仍解不出的实例。

下一步判断规则很清楚：

- 如果 ResidualProgressDiverse 最终仍然只有 1 到 2 个上界命中，就不应该继续调选择器，而应该继续改训练目标，例如更强的剩余实例定向训练、难例微调、样本多样性目标、以及面向 March/CaDiCaL 都失败实例的奖励设计。
- 如果最终达到至少 5 / 49 个上界命中，才进入下一阶段：只在开发集上冻结选择器阈值、预算规则和非神经对照日程，然后在保留测试集上一次性评估。

## 十四、汇报结论

这个项目不是从一个方法一路简单调参，而是经历了清晰的研究问题升级。

原始 RLAF 解决了“神经网络能否给求解器一次性引导”的问题。

Balanced Improver 进一步解决了“能否利用求解器反馈改进引导”的问题。

选择器阶段解决了“什么时候启用神经引导才不容易变慢”的问题。

当前剩余实例组合求解主线，则把问题推进到最严格也最有说服力的形式：

> 强求解器都失败后，神经方法是否仍有互补搜索价值。

目前的实验效果可以概括为：

> 早期和中期结果证明方向有效，但当前顶会性能主线还没有过关。现阶段最大的风险不是协议，而是模型在强求解器剩余实例上的覆盖率不足。只有当上界采样覆盖率提高之后，固定选择器和同预算非神经对照才值得继续推进。
